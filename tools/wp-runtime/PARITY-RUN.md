### Known harness limits

- Listeners never fire and DOM queries return empty: form injection, link decoration,
  WhatsApp append and consent flows cannot be exercised here (all explicitly out of scope
  in docs/WP-PARITY-DRAFT.md). This harness proves QUERY/REFERRER CLASSIFICATION parity only.
- The plugin writes through its full storage stack (cookie + localStorage mirror +
  sessionStorage fallback). We read the dataLayer push rather than re-reading storage, so
  storage-envelope bugs would not surface here.

## Observations from live execution

- **Click-ID ft_/lt_ mirror**: the plugin duplicates every captured click ID into
  `ft_<cid>`/`lt_<cid>` touch fields (`mapQueryFields` output goes through `applyTouch`,
  :1813-1837 + :1788-1799), while the TS engine stores click IDs top-level only
  (`mergeAttributionTouch`). Static analysis missed this. It only shows up in the five
  click-ID fixtures, which are all covered by rulings #1/#2 anyway, so those rows are
  marked RULED DIFF — but the storage-model difference itself deserves supervisor
  confirmation before Phase 2 freezes.
- **Timestamps compare exactly**: with the pinned Date the plugin emits the same
